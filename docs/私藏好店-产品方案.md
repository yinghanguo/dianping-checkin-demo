# 「私藏好店」产品方案

> 产品方案 V1.2 · 2026 年 7 月
> 上游文档：[私藏好店-产品计划书.md](./私藏好店-产品计划书.md) · 可交互原型：https://yinghanguo.github.io/dianping-checkin-demo/
> V1.1 修订：① 收藏关系改为"专辑接电"模型（一个对象三种状态）；② 打卡与足迹合并为「打卡足迹」；③ 明确清单微信分享能力与共享专辑/内容项边界。
> V1.2 修订：① 客态个人主页回归并与主态差异化（默认锚定公开清单）；② 新增地图分发（三态结构 + 清单地图模式）；③ 门店页收录模块定位于评价楼层"信任区"；④ 清单互动区移至封面右上角；⑤ 拔草进度统一口径（手动勾选 ∪ 真实打卡）。
> V1.3 修订：① AI 边界收窄——去掉创作/代写类 AI，只保留选店层面的辅助筛选；② 创作者"去过"标签全链路下线（保留为内部分发信号与"我的拔草"维度）；③ 清单项多图（横滑展示 + 编辑器增删/上传）；④ 选店改为「从我的发布选店」，类目 + 地点双维筛选；⑤ 可见性后置：默认公开、发布时校验弹窗可降级私密；⑥ 清单地图取消点间连线；⑦ 清单尾部"同主题的其他作者私藏"仅公域流量展示。

## 一、方案概述与范围

本方案将计划书落地为功能级设计，覆盖 **Phase 1（工具期）+ Phase 2（分发期）** 的全部产品能力：

**本期做：**
1. 清单的创建与编辑（存量转化 / 顺手收集 / 主动创建三条路径）
2. 清单详情页（消费、互动、拔草）
3. 个人主页「TA 的私藏」模块
4. 门店详情页收录模块 +「收入私藏」按钮
5. 搜索结果页清单卡片穿插
6. 信息流清单卡片与好友动态
7. 私密 / 公开体系（清单体系升级替代收藏体系）

**本期不做（Non-goals）：**
- 清单商业化能力（计划书明确早期一律不可商业化）
- 清单协作共建（多人编辑一份清单）
- 跨城市清单聚合频道 / 独立清单 Tab
- 评论区（互动仅点赞、收藏、订阅，控制冷启动期的运营负担）

## 二、信息架构

### 2.1 清单对象在 App 中的位置

```
大众点评 App
├── 首页信息流 ──────────── 清单卡片（分发）／好友更新事件（分发）
├── 搜索结果页 ──────────── 清单卡片穿插（分发）
├── 门店详情页
│   ├── 「收入私藏」按钮 ──── 创作入口
│   └── 「被收录」模块 ────── 分发 + 背书
├── 个人主页（我的 / TA 的）
│   └── 「私藏」一级 Tab ──── 存放（公开清单 = 品味橱窗；私密清单仅自见）
├── 清单详情页 ──────────── 消费主场景
└── 清单创建 / 编辑页 ────── 创作主场景
```

### 2.2 与收藏体系的关系（关键决策，V1.1 修订）

**现状盘点**：点评收藏页已有「专辑」体系——多店集合 + 主题名、共享人机制、被收藏数、「我收藏的」Tab、一键导入与创建入口，专辑还可挂内容。工具层基本齐备，缺的全在**表达层与分发层**（专辑普遍 0 人收藏：不是用户不整理，而是整理完没有被看见的机会）。

**因此私藏好店不新建体系，而是给专辑"接电"——一个对象，三种状态：**

```
收藏一家店 ──→ 归入专辑 ──→ 补一句理由 + 公开 ──→ 私藏清单
（平铺仓库）    （结构化整理·私密）   （表达 + 分发·公开态专辑）
 地点/商户 Tab      专辑 Tab             专辑 Tab · 公开角标
```

- **收藏** = 容器体系总名；平铺的地点/商户列表保留（区域/分类筛选是工具刚需）。
- **专辑** = 收藏的结构化形态，默认私密，纯工具（即今天的样子）。
- **私藏清单** = **公开态的专辑**，不是第三种东西。专辑满足公开门槛后一键公开，公开那一刻获得：人格门面、去过标、店页/搜索/信息流分发资格、被订阅与拔草的能力。

**专辑 → 清单的差距（按优先级）**：① 每店一句话理由字段；② 封面体系——现专辑封面为商家营销头图，公开清单必须优先用户自己的照片（否则分发出去是广告墙）；③ 真实去过信号（与打卡足迹打通，V1.3 起仅内部加权、不外显）；④ 公开开关 + 分发准入；⑤ 订阅更新与拔草（挂在已有「我收藏的」Tab 上）。

**边界**：公开能力首期只给单人专辑（共享专辑保持私域协作，后续再考虑"主理人制"）；清单只认地点/商户，不收内容（避免滑向"合集笔记"）。

## 三、核心对象与数据模型

### 3.1 清单 List

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 唯一标识 |
| ownerId | string | 创作者 |
| title | string | 主题名，≤20 字，必填（如"梧桐区适合二人安静吃饭的店"） |
| description | string | 简介，≤100 字，选填 |
| cover | image | 封面：默认取清单内前 4 家店照片拼图，可自定义 |
| visibility | enum | `private`（默认）/ `public` |
| items | ListItem[] | 清单项，公开清单要求 ≥3 项 |
| likeCount / saveCount / subscribeCount | int | 互动计数 |
| healthScore | float | 健康度（见 6.4），系统计算，不外显数值，仅影响分发 |
| createdAt / updatedAt | time | updatedAt 驱动"更新即再分发" |

### 3.2 清单项 ListItem

| 字段 | 类型 | 说明 |
|---|---|---|
| poiId | string | 门店 |
| reason | string | **一句话理由，5–50 字，公开清单必填**（结构化最低要求） |
| photos | image[] | 多图（V1.3），首图为封面；优先自动带入该用户在此店的发布图，支持增删与本地上传，展示端横滑 |
| beenThere | bool | 系统判定：创作者在该店是否有打卡 / 评价 / 消费凭证。**V1.3 起不再外显**（没去过大概率也不会收录，标签价值低），仅作为内部分发信号保留 |
| addedAt | time | 用于"新增"角标 |
| status | enum | `normal` / `closed`（门店闭店时系统自动标注） |

### 3.3 用户与清单的关系

| 关系 | 行为 | 效果 |
|---|---|---|
| like | 点赞 | 轻互动，计数，给创作者反馈 |
| save | 收藏清单 | 清单进入我的「私藏-收藏的清单」，可拔草 |
| subscribe | 订阅 | 收藏时默认勾选"清单更新时提醒我"；更新触发推送/红点 |
| checkOff | 拔草勾选 | 收藏者对清单内单店标记"去过了"，个人维度存储，不影响他人 |

### 3.4 门店与清单的关系（反向索引）

门店维度维护 `includedInLists`：被哪些**公开**清单收录、总收录数、按分发分排序的 Top 清单——支撑门店页收录模块与搜索加权。

## 四、核心流程

### 流程 A · 创作：三条路径汇入同一个编辑器

```
A1 存量转化（系统发起）        A2 顺手收集（场景内）           A3 主动创建
────────────────────      ─────────────────────      ─────────────
"你打过卡的咖啡店已有23家"      门店页「收入私藏」               个人主页「+新建清单」
消息卡片 / 我的页气泡           评价发布成功页追问                      │
      │                            │                             │
      ▼                            ▼                             │
AI 生成草稿清单               选择清单弹层（半屏）                     │
（标题+店+理由草稿）           - 最近使用的清单置顶                    │
      │                     - 可当场新建                          │
      ▼                            │                             ▼
   清单编辑器  ◄───────────────────┴───────────────────►  清单编辑器（空态）
      │
      ▼
保存（默认私密）──→ 满足公开门槛时，展示"公开"引导
```

**A1 存量转化的触发规则**：
- 触发条件：用户在同一品类（或同一商圈）有 ≥5 家打卡 / 4 星以上评价的门店。
- AI 的边界（V1.3）：**只做选店筛选，不做任何代写**——按品类/地域圈出门店集合（按用户评分/回访次数排序）；标题与推荐理由由用户自己写，理由输入框带入该用户自己发布过的原文（数据复用，非生成）。编辑器选店 sheet 另有「AI 按主题筛」：按当前清单的多数类目圈候选。
- 频控：每用户每月最多收到 2 次草稿邀请；忽略 2 次后该品类不再触发。

**A2 选择清单弹层（收入私藏）**：
- 半屏弹层：清单列表（最近使用置顶）+「新建清单」；选中即完成，Toast「已收入 ×× ✓ 补一句推荐理由」，点 Toast 直达该项的理由输入。
- 理由可跳过——私密清单不强制理由，公开时才校验。

### 流程 B · 公开门槛与发布拦截（V1.3 修订：默认公开）

清单**默认公开**，可见性开关位于编辑器最底部。公开门槛不变：
1. 门店数 ≥3；
2. 每店理由已填写；
3. 清单标题非默认名。

校验时机后置到**点「发布」时**：不达标弹窗列出缺失项，提供两条路——「改为私密并发布」（先存后补，随时可再公开）或「继续完善」。私密清单达标后，详情页仍有"公开我的私藏"引导。

### 流程 C · 消费：发现 → 浏览 → 收下 → 拔草

1. **发现**：店页收录模块 / 搜索穿插 / 信息流 / 好友主页。
2. **浏览**：清单详情页；每店卡片可直接跳门店页（消费闭环回到店）。
3. **收下**：收藏清单（默认勾选订阅更新）。
4. **拔草**：在自己收藏的清单里勾掉去过的店，进度外显「已去 3/8」；全部拔草时触发彩蛋（"这份私藏你已吃完 🎉 看看 TA 的其他清单"）。**口径统一（V1.2）**：我的拔草进度 = 手动勾选 ∪ 我的真实打卡（打卡过的店自动算去过、不可取消），全端共用同一计算，与"作者去过"（创作者维度）在文案上明确区隔。
5. **召回**：订阅的清单有新增门店 → push +「私藏」Tab 红点：「你收藏的《××》更新了 2 家店」。

## 五、页面与交互详设

### 5.1 清单详情页（消费主场景）

**页面结构（自上而下）：**

| 模块 | 内容 | 交互 |
|---|---|---|
| 头部 | 封面拼图、标题、简介 | — |
| 创作者条 | 头像、昵称、等级/达人标、"关注" | 点击进个人主页 |
| 信息条 | 「N 家店 · 更新于 X」 | V1.3 起不再外显"作者去过"（保留为内部分发信号）；"我的拔草"维度照常 |
| 互动区（V1.2：封面右上角） | 点赞(带计数) / 收藏(+订阅) / 分享 胶囊按钮组 | 页面全滚动阅读，无底部栏；分享生成微信卡片 |
| 店卡列表 | 每店：照片（**多图横滑** + 张数角标）、店名、品类/商圈/人均、**一句话理由（视觉主体）**、（收藏者视角）拔草勾选框 | 点卡片进门店页 |
| 尾部 | 「TA 的其他私藏」横滑；**公域流量额外追加「同主题的其他私藏」**（其他作者，按主题类目 + 门店重叠匹配） | 人→店→人的循环；公域才做跨作者推荐，私域（用户查询的就是这个作者）不加 |

**关键设计原则**：一句话理由是店卡的视觉主体（大字号），门店客观信息弱化——这个页面卖的是"他为什么选这家"，不是店铺档案。

**状态**：闭店的店卡置灰 +「已歇业」标，不计入拔草进度；创作者视角店卡右上有「编辑」浮标。

### 5.2 清单编辑器（创作主场景）

- 标题（必填，**用户自己写，无 AI 生成**）、简介（选填）、封面（默认取首店首图）。
- 店卡列表：拖拽排序、左滑删除；每店理由输入框带占位文案（"为什么是这家？一句话就够"）；有该店打卡/评价图时自动带入首图。
- 「+ 添加门店」：搜索添加 + 「**从我的发布选店**」（V1.3：打卡/评价/收藏聚合选择器，多选批量加入，支持**类目筛选**——美食/咖啡/酒店/景点/SPA/购物/运动/其他——与**地点筛选**双维度，另有「AI 按主题筛」）。
- 每店照片可增删与本地上传，首图为封面（V1.3）。
- 可见性位于清单最底部，**默认公开**（V1.3）；头部主按钮为「发布」。
- 草稿自动保存，中途退出不丢失。

### 5.3 个人主页与「我的」页（V1.2 修订：主客态差异化）

**数据卡片三联**（打卡与足迹合并——打卡是动词留给行为入口，足迹是名词归入资产模块）：

| 卡片 | 内容 | 点击去向 |
|---|---|---|
| **打卡足迹** | 累计打卡 N 次 · X 国 Y 城 | 打卡足迹页（地图 + 时间线，沿用现有打卡模块） |
| **收藏（含清单）** | N 家店 · M 份清单 | 收藏页 |
| **口味档案** | 累计用餐 · 解锁菜系 | 口味档案页 |

三联恰好构成个人资产三元组：**足迹（我去过哪）· 收藏含清单（我留下了什么）· 口味档案（我吃成了什么样）**。足迹是清单的原料库（从足迹选店、AI 草稿、去过标均来源于此）。

**收藏页改造**（对齐现有真实结构，改动最小化）：
- 顶部 Tab 保持「专辑｜地点/商户｜推荐菜｜内容｜商品｜其他」。
- 专辑 Tab 下保留「我的专辑｜我收藏的」切换：我的专辑卡片增加**公开/私密角标与被收藏数**（公开的即私藏清单）；「我收藏的」承接别人的清单 + 拔草进度。
- 底部保留「一键导入｜创建专辑」。

**客态个人主页（与主态差异化）**：主态强调资产沉淀（去过哪、发过什么），客态强调"给别人看的东西"——
- 头部：头像 / IP / 等级 /「私藏达人」徽章（被藏达标点亮）、粉丝·关注·**获赞与被藏**（被藏计入荣誉数）、一句话人设简介、轻量资产条（打卡足迹与口味档案**只给聚合数，不暴露具体轨迹**）、关注 + 私信。
- 内容 Tab：**私藏（默认锚定，公开清单即品味门面）**｜动态｜评价——"评价"直接复用清单里的一句话理由（标注收录来源，可跳回清单），理由资产获得二次分发。

**分享能力**：清单支持分享到微信（单人清单均可分享，创作者与消费者视角皆有入口）；微信侧为小程序卡片（四宫格封面 + "✓ 全部去过"信任标 + 创作者头像），落地为只读清单页，见 5.7。

### 5.4 门店详情页（两处改造）

1. **「收入私藏」按钮**：与收藏同位置（原收藏按钮直接升级），点击唤起选择清单弹层（流程 A2）。
2. **「被收录」模块**（V1.2 定位）：门店页为锚点楼层结构（优惠/推荐菜/评价依次平铺，点 Tab 跳楼层），被收录模块放在**评价楼层顶部的"信任区"**——评价标签 → 关注的人来过 → 被 N 份私藏收录 → 大众评价流。它与"关注的人来过"是同一物种（人格化信任信号），压在陌生人评价之上，而非挤占优惠首屏与商家冲突。
   - 标题：「被 47 份私藏收录」，副题「TA们为什么私藏这家」（V1.3：不再用"去过"表述）。
   - 内容：按分发分排序的 Top 3 清单条（创作者头像+清单名+"含此店理由"摘录），横滑。
   - 收录数 <3 时模块不出现（避免暴露冷清）。
   - **理由摘录直接展示**——用户在店页就能看到"别人为什么私藏这家店"，这是比评分更立体的背书，也是清单获得点击的钩子。

### 5.5 搜索结果页穿插

- 触发：搜索词命中清单标题/品类/商圈，且候选清单分发分达标。
- 位置：第 4 位后穿插 1 张，每页最多 1 张。
- 卡片：封面拼图 + 标题 + 创作者 + 「N 家店 · 全部去过 ✓」+ 收藏数；样式与店铺卡明显区隔（人格化：头像前置）。
- 首期只在高决策品类开启：约会餐厅、宴请、深夜食堂、本帮菜等（配置化品类白名单）。

### 5.6 信息流卡片

- **清单卡片**：四宫格封面 + 标题 + 创作者 + 理由摘录一条。
- **好友事件卡**：「好友 ×× 公开了私藏《××》」/「好友 ×× 的《××》上新 2 家店」。
- 分发权重：好友清单 > 同城达人清单 > 其他（对应"朋友的清单权重高于网红的清单"）。

### 5.7 微信分享卡片

- 分享标题：「我私藏的 N 家店：《标题》」；缩略图用封面拼图。
- 落地页（站外 H5）：只读清单详情，底部「在点评中打开，领走这份私藏」（打开后自动收藏）。

### 5.8 地图分发（V1.2 新增）：三态结构

信息流分发的是"内容"，地图分发的是"决策"——打开地图的人带着"我在这附近、要选一家"的意图，是清单对评分替代优势最大的时刻；清单反过来给地图带来"路线感"。

| 状态 | 触发 | 地图 | 底部卡片流 |
|---|---|---|---|
| **默认态** | 进入地图 | 热门门店评分 pin | 门店卡 |
| **私藏态** | 点右侧「私藏」浮钮（与必吃榜并列的人格图层） | 热门门店不变，评分胶囊**追加"🔖 N"收录段**（无收录的店不带标） | 切换为**清单列表**（封面 + 创作者 + 作者全部去过 ✓ + 互动数 +「上图」） |
| **清单态** | 点选一份清单 | **只呈现该清单门店**：独立序号 pin（V1.3：**不加点间连线**），视野自动缩放；拔草状态画在 pin 上（去过=绿✓） | 清单头（返回 / 完整清单入口）+ 带一句话理由的序号店卡，与 pin 双向联动 |

- 进入清单列表的条件：公开 + 全部门店可上图 + 在当前城市范围，按互动排序。
- 清单详情页内嵌同款「清单地图模式」（📍 N 家店 · 已去 M）：各店独立标点，不做连线（V1.3——清单是店的集合，不预设行走顺序）。
- 密度控制是生死线：私藏标记只做追加不做替换，图层由用户开关。
- Phase 3 预留：附近拔草提醒（我收藏的清单里有店进入附近 500m → pin 呼吸高亮 + push），空间触发的召回循环。

## 六、关键规则

### 6.1 公开与分发准入（两道门）

- **公开门槛**（用户可控）：≥3 店、理由齐全、非默认标题。
- **分发准入**（系统判定，进入店页/搜索/信息流公域的条件）：公开 + 健康度达标 + 创作者信用正常。公开但未达分发准入的清单仅出现在主页与站外分享——保证公域质量，不打击创作。

### 6.2 「真实去过」加权（V1.3：只做内部信号，不外显）

- **展示层不再出现任何"作者去过"标签**——没去过的店用户大概率也不会收录，标签的信息量低；信任交给理由文本与创作者人格本身。
- ListItem.beenThere 由创作者在该店的打卡 / 评价 / 消费凭证判定，仅用于内部分发加权与反作弊。
- 分发分中 beenThere 覆盖率仍是重要权重因子——**没去过也能建清单（不禁止攻略型整理），但公域分发偏向真实足迹**。

### 6.3 反商业化（Phase 2 上线前必须就位）

- 清单无任何商业化入口；创作者协议明示"收钱代收录"违规。
- 算法信号：多份清单店铺高度重合、短期集中新增同一门店、新注册账号高频建单 → 降权 / 送审。
- 用户举报入口：清单详情页「举报 · 疑似推广」。
- 违规处置：清单退出公域分发，创作者信用分扣减，二次违规封禁公开能力。

### 6.4 健康度与腐烂治理

- 健康度 = f(闭店率, 理由完整度, 最近更新时间, 负反馈率)。
- 门店闭店 → 清单内自动标注，推送创作者：「你的《××》中 1 家店已歇业，去看看 →」——**把维护变成有回报的事**：编辑更新后 updatedAt 刷新，触发订阅者召回与再分发。
- 健康度过低的清单自动退出公域（不通知、不删除，修复后自动恢复）。

现有 demo 的「专辑」（`src/data/albums.js`：title + items[poi, photo, caption]）即清单雏形，原型按以下路径升级：

| 门店页收录模块 | `pages/StoreDetail.jsx` | 新增「被 N 份私藏收录」模块 + 收入私藏按钮 |
