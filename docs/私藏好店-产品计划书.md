## 〇、一页读懂

- **做什么**：把点评十几年只有"品类→店"的找店路径，补上"人→店"——让"会吃的朋友"的品味被产品化成**清单**，并在店页/搜索/信息流/好友页/地图/站外分享六个主链路分发。
- **本质**：把点评的信任资产从"店的评分"扩展到"人的品味"。评价回答"这家店怎么样"，清单回答"这个人会带你去哪"。
- **怎么落地**：不新建体系，给点评已有的「专辑」接电——收藏 → 私密专辑 → 补一句理由 + 公开 = 私藏清单（一个对象三种状态）。
- **怎么增长**：以城市运营活动 **「私藏杯」** 引爆——创作者提报清单、用户收藏后**真实到店打卡**决出冠军，一场活动同时拉动供给（清单大扫除）、消费（照着去）、关系（收藏即订阅种子）。
- **最大风险**：商业化污染信任。清单信任模型比评分脆弱，早期一律不可商业化，活动零冠名、奖励零现金。
- **成败前提**：点评是否真的敢在门店页和搜索里给"人的清单"留出一级位置。

## 一、项目背景与机会

用户在点评上找店的路径，十几年来只有一条：**品类 → 店**（搜索、榜单、评分）。但现实世界里存在另一条更高信任度的路径：**人 → 店**——"问那个会吃的朋友"。这个行为今天发生在微信对话框里（"发我你那个火锅清单"），点评并没有承接它。

「私藏好店」要做的，就是把这条路径产品化：让"会吃的朋友"的个人品味被便捷地创作成清单，并在信息流、好友列表、搜索结果页、门店详情页等主链路分发。

**核心判断：私藏好店的本质，是把点评的信任资产从"店的评分"扩展到"人的品味"。** 评价回答"这家店怎么样"，私藏好店回答"这个人会带你去哪"。

## 二、产品定义：私藏好店是什么

### 2.1 与现有体系的坐标关系

| | 单元 | 信任基础 | 时效性 | 资产归属 |
|---|---|---|---|---|
| 评价 | 单店单次体验 | 统计信任（量大取平均） | 低衰减 | 店 |
| 打卡 | 单店行为记录 | 无（"我来过"的足迹） | 无 | 人（足迹） |
| 官方榜单 | 多店集合 | 平台信任（算法与规则） | 周期更新 | 平台 |
| **私藏好店** | **多店 + 一个主题口径** | **品味信任（信这个人）** | **低衰减，且可持续更新** | **人** |

官方榜单是"统计的答案"，私藏好店是"某个人的答案"，二者在分发场景中互补并存。

### 2.2 三个独有属性

1. **它是策展，不是记录。** 价值不在单店信息，而在选择与排除——"他只放了这八家"本身就是信息。评价越多越准，清单越少越贵。
2. **它是活的文档。** 可以持续增删维护，因此具备"订阅"价值：死内容只能被消费一次，活清单让人反复回来。
3. **它以人为索引。** 第一次为点评提供"人 → 店"的找店路径，是"会吃的朋友"这一现实行为的产品化。

**类比：私藏好店之于门店，如歌单之于歌曲。** Spotify 的歌单没有生产任何新歌，但重构了消费入口，并让"品味"本身成为可关注的对象。

### 2.3 产品形态最低规格

- 清单 = 主题 + N 家门店 + **每店一句话理由**（结构化最低要求）。
- 没有理由的清单是店铺堆砌，"他家只有中午去才有那个汤"才是品味的证据。
- 支持私密 / 公开两种状态，公开只是一个开关。

## 三、产品现状（原型已落地）

> 本节按可交互[原型](https://yinghanguo.github.io/dianping-checkin-demo/)盘点已落地的产品形态，作为下文路径设计与增长活动的实物基础。功能级细节见[产品方案 V1.3](./私藏好店-产品方案.md)。

### 3.1 一个对象，三种状态（存放体系已跑通）
收藏页顶部即「专辑」Tab，分「我的专辑」与「我收藏的」；地点/商户平铺仓库保留为工具刚需。收藏一家店 → 归入专辑（私密整理）→ 补理由 + 公开 = 私藏清单，三态连续、不新建体系。

### 3.2 创作侧：把创作摊进日常
- **草稿箱**：把用户近期打卡按类目自动归置成待整理草稿（如"咖啡 9 家 / 美食 N 家"），个人页 banner 的内容推荐即来自草稿箱——存量转化从"命令用户创作"变成"帮他把料理好、只等发布"。
- **编辑器**：「从我的发布选店」（地点 + 类目双维筛选）；自己发布过的内容**照片与理由自动代入**，无需手动添加；每店一句话理由（≤50 字，公开必填）；默认公开、发布时不达标可一键降级私密。
- **无 AI 代写**：AI 只做选店层面的辅助筛选，标题与理由全部用户自己写——守住"真实"底线。

### 3.3 分发侧：六个主链路已接通
门店详情页「被 N 份私藏收录」信任模块 +「打卡即助攻」活动角标；搜索结果页第 2 商户后**清单与笔记混排横滑**；信息流清单卡片；好友页清单动态事件（"公开了/更新了私藏清单"，与发布内容同构）；首页「附近」Tab 分发附近的公开清单；**地图**三态（私藏图层 → 查看门店列表 → 清单落图）；站外微信分享卡。

### 3.4 消费与信任：去过=行为，不靠手填
清单的「拔草 / 去过」进度**纯由用户真实行为（打卡 / 评价 / 消费）自动判定，禁止手动勾选**——避免"顶部说全部去过、进度却是 0"的口径漂移，也让"真实去过"成为可信的分发加权信号（内部使用，不外显倍数）。

### 3.5 增长活动：私藏杯已进原型
活动主会场（提报 / 开赛双阶段）、店页「打卡即助攻」角标、个人页与首页的分阶段 banner 投放均已在原型中演示（详见第六节）。

## 四、产品路径设计

### 4.1 创作：清单是"攒"出来的，不是"写"出来的

若做成从零开始的创作任务，供给必然起不来。入口按成本从低到高分三层：

**① 存量转化（最重要）**
- 收藏夹一键生成清单——收藏本来就是未整理的清单。
- 从历史打卡 / 高分评价反向聚合：系统主动提示"你打过卡的咖啡店已有 23 家，整理成一份私藏好店？"，AI 生成草稿，用户只做删减和补一句话理由。

**② 顺手收集**
- 门店页新增"收入私藏"按钮（类似加购物车）。
- 写完评价后追问："要把这家店加进你的某个清单吗？"
- 让创作分散在日常使用中，而非集中于一次创作。

**③ 主动创作**
- 个人主页"新建清单"，服务头部创作者。

### 4.2 分发：清单在哪被看见

按分发效率排序：

| 场景 | 形式 | 逻辑 |
|---|---|---|
| **门店详情页** | 高互动清单模块 +「被 N 份私藏收录」标签 | 店是天然流量入口，借店的流量给人导流；清单反向为店提供比评分更立体的背书 |
| **搜索结果页** | 店铺结果中穿插清单卡片 | 命中高决策成本场景（约会、请客、带外地朋友）——用户要的不是排序，是"一个靠谱的人替我选好" |
| **信息流** | 清单卡片（封面拼图 + 主题 + 创作者）、"好友更新了私藏"关系链事件 | 品味浏览与关系链消费 |
| **好友列表 / 个人主页** | "TA 的私藏"一级入口 | 人 → 店路径的起点 |
| **地图**（V1.1 新增） | 「私藏」图层（与必吃榜并列）：热门门店 pin 追加收录标记 → 底部清单列表 → 点选后清单门店连成路线上图 | 信息流分发内容，地图分发**决策**；清单在地图上变成"可以走的路线"，从决策工具升级为行动工具 |
| **站外分享** | 精致的微信卡片 | "发我你那个清单"是已存在的真实需求，最便宜的外部增长 |

### 4.3 存放：工具与表达合一

存放位置决定产品性质：放在"收藏"是工具，放在"个人主页"是表达。**答案是两者合一**：

- 清单不新建体系，而是给点评已有的「专辑」接电：收藏一家店 → 归入专辑（私密整理）→ 补一句理由 + 公开 = 私藏清单。一个对象三种状态，工具层已存在，缺的只是表达层与分发层。
- 公开清单成为个人主页一级门面——"品味橱窗"。
- 私密工具价值兜底 100% 用户的使用理由，供给漏斗自然形成：**收藏 → 私密清单 → 公开清单**。

## 五、用户与增长

### 5.1 目标用户：创作金字塔，消费全量

| 层级 | 占比 | 画像 | 角色 |
|---|---|---|---|
| 头部 | ~1% | "会吃的朋友"：高等级会员、精评达人、本地 KOC | 提供分发级供给 |
| 腰部 | ~5–10% | 有整理欲的重度用户，为发朋友、为主页好看而创作 | 供给主力与扩散层 |
| 长尾 | 100% | 把清单当私密收藏工具 | 不是创作者，但是腰部与头部的蓄水池 |

消费侧为全量决策用户，优先覆盖高决策成本场景：宴请、约会、出差、陪外地朋友。

### 5.2 冷启动策略

1. **供给不靠激励靠存量**：点评手握全网最好的原料——十几年的评价、打卡、收藏数据。用 AI 为高等级用户生成草稿清单，定向推送"一键认领发布"，第一批供给近乎零成本。
2. **定向邀请 + 官方打样**：按城市邀请美食 KOC 做种子创作者，官方与达人共创标杆清单（如"上海本帮菜十年老饕的 12 家"），定义什么是好清单。
3. **打透一两个城市**：清单价值依赖同城密度，全国摊开等于没有。先在上海或成都做到"搜任何主流品类都能撞到好清单"，再复制。
4. **选对首发场景**：从"问朋友才敢决策"的品类切入——约会餐厅、请客、深夜食堂——这些场景下清单对评分的替代优势最大。

### 5.3 规模化飞轮与 DAU

**飞轮**：店页 / 搜索给清单曝光 → 清单获得点赞收藏 → 创作者得到反馈持续维护 → 更新触发再分发。平台要保证的是第一环：冷启动期分发流量向清单倾斜。

**对 DAU 保持诚实**：点评是低频决策工具，清单不会把它变成小红书。但它带来两类真实的频次增量：

- **创作者的维护频次**：清单是活的，需要回来修剪。
- **消费者的"拔草"回访**：用户收藏清单后可勾掉去过的店——清单变成待办列表，制造明确的回访理由；叠加"你订阅的私藏更新了"的召回，建立点评目前缺失的"订阅—更新"内容循环。

**合理预期：留存和决策渗透先动，DAU 后动。**

## 六、增长引擎：私藏杯活动

产品把"人 → 店"的路径铺好了，还需要一个**引爆点**让创作和消费在同一时间集中发生。答案是城市运营活动 **「私藏杯」**——它不是附加的市场活动，而是分发期（Phase 2）的核心增长手段。完整方案见[私藏杯活动策划 V1.3](./私藏好店-清单PK活动策划.md)，此处只讲它为何并入计划书、以及与产品节奏的咬合。

### 6.1 为什么用一场活动引爆
清单产品有个先天难题：**没人看 → 没人写，没人写 → 没人看**。日常运营解不开这个死结，但一场有赛程、有悬念、要用脚投票的比赛可以——它在同一窗口里同时点燃三件事：
- **供给**：报名门槛 = 公开门槛，活动本身就是一次全城清单质量大扫除；
- **消费**：收藏清单 → 照着去打卡 → 打卡就是给创作者助攻，消费第一次有了"参与一场比赛"的意义；
- **关系**：收藏了参赛清单的用户，就是 Phase 3「订阅—更新」循环的第一批种子——比赛结束那天，订阅关系已经建好。

### 6.2 玩法核心：种草—拔草结算制
创作者限期提报清单 → 开赛 3 周开放收藏 / 投票 / 打卡 → **以"收藏用户的真实到店打卡数"结算冠军（打卡王）**。关键设计：
- **冠军由行为决出，不由票数决出**：投票只进人气榜（过程分发依据），真实到店打卡进拔草榜（结算榜）。别吵了，用脚投票。
- **商圈 / 主题是灵感，不是赛道**：55 个标准商圈 + 18 个生活场景主题，只作创作者的选题灵感与清单标签；从「比赛」入口进编辑器时按内容推荐标签一键挂载。全员参赛，设「授奖线」兜底（拔草 <100 不授奖）。
- **计分防操纵**：人×店去重、每人每清单封顶 3 家、单店占比 ≤40%、打卡须发生在收藏之后——保证归因方向是"清单把人带到店"。

### 6.3 奖励与信任底线
- **奖励只给荣誉、分发与体验，不给现金**：打卡王得冠军徽章 + 2 周分发加权 + 官方共创；全场奖上体验型重奖（人气王 = Asia's 50 香港美食之旅、黑马奖 = 黑珍珠三钻双人餐）；用户侧投票零奖励、打卡阶梯抽奖（美食满减券）、伯乐奖（投中打卡王且打卡最多者得无门槛券）。
- **零冠名、零商户赞助、零现金**：奖品平台统一采购；利益换票 / 商户合谋一经查实取消资格并公示。这条直接护住第七节的最大风险——商业化污染信任。

### 6.4 分发投放与产品节奏咬合
- **投放**：提报期主会场面向创作者（大奖前置 + 投稿入口），走个人页 banner；开赛期面向消费者（玩法规则 + 用户奖），走首页中通 banner + 侧边栏常驻；店页「打卡即助攻」角标是拔草计分的临门一脚。
- **节奏**：私藏杯是 **Phase 2 的引爆点**（把分发效率与信任耐受度在真实流量下压测一次），其沉淀的"收藏—打卡"归因管道，赛后即成为「经清单到店」的常规指标，并把种子关系交棒给 **Phase 3 的订阅—更新循环**。

## 七、风险与对策

按严重程度排序：

### 7.1 商业化污染信任（最大卡点）

点评的立身之本是真实性，而清单的信任模型比评分更脆弱——评分靠量对冲水军，清单只要创作者被收买一次就整体崩塌。一旦"推广清单"混入分发，用户对整个体系的信任会连坐。

**对策（必须前置）：**
- 早期清单一律不可商业化。
- "真实去过"加权：清单内门店有创作者本人打卡 / 消费凭证的，分发权重更高。
- 对店铺密集重合、集中新增的清单做算法识别与降权。

### 7.2 供给冷启动悖论（没人看 → 没人写）

**对策**：私密工具价值兜底，让创作在无人观看时也成立（见 4.3）。

### 7.3 马太效应

头部达人吃掉全部分发，普通人失去动力。

**对策**：分发上"朋友的清单"权重高于"网红的清单"。这也是点评相对小红书的差异化——小红书给你陌生人的种草，点评给你**认识的人的私藏**。

### 7.4 清单腐烂

店会关、会变味，清单随时间失效。

**对策**：闭店自动标注、清单"健康度"分、更新行为触发再分发（把维护变成有回报的事）。

## 八、产品命名：私藏好店

产品定名 **「私藏好店」**，个人主页入口为 **「TA 的私藏」**。理由：

1. **征用现成心智**："这是我私藏的店""分享几家私藏"是用户已经在说的话，零教育成本。
2. **自带信任与稀缺感**："私藏"暗示不是广告、不是榜单，是我不轻易告诉别人的东西——正面对冲 7.1 的信任风险。
3. **与产品路径严丝合缝**：收藏 → 私藏 → 公开私藏；"公开我的私藏"这个动作本身就有社交张力，是天然的传播语。

## 九、里程碑规划

> 说明：Phase 1–2 的产品能力已在[可交互原型](https://yinghanguo.github.io/dianping-checkin-demo/)中全部演示（见第三节），以下里程碑给出上线与验证节奏；**私藏杯活动是 Phase 2 的引爆点、Phase 3 循环的种子来源**。

### Phase 1：工具期（1 个月）｜创作漏斗
- 收藏体系升级为清单体系，私密 / 公开开关、每店一句话理由、门店页"收入私藏"。
- 存量转化：草稿箱按类目自动归置近期打卡 + 一键接着编（无 AI 代写）。
- 个人主页"TA 的私藏"模块、拔草进度改为行为自动判定。
- **目标**：验证创作漏斗——收藏 → 私密清单 → 公开清单的转化率。

### Phase 2：分发期（1–2 个月）｜分发效率 + 活动引爆
- 六大分发触点全量：店页「被收录」+「打卡即助攻」、搜索混排、信息流 / 好友页清单事件、附近 Tab、地图三态、微信分享。
- **私藏杯 · 城市站活动**（种子城市上海）：提报 → 3 周收藏 / 投票 / 打卡 → 真实到店打卡结算冠军；分阶段 banner 投放 + KOC 定向邀请 + 官方共创标杆清单。
- **目标**：验证分发效率（清单卡点击率、清单→到店转化）与活动引爆力（提报量、拔草率、活动带来的收藏关系）。

### Phase 3：循环期（2–3 个月）｜留存循环 + 复制
- 清单订阅与更新召回（承接私藏杯沉淀的"收藏—订阅"种子关系）。
- 反作弊全量（真实到店加权、商业密度 / 商户合谋识别）。
- 城市复制 + 私藏杯第二期（守擂制 / 城市德比）。
- **目标**：验证"订阅—更新"循环对留存的拉动，与活动模型的可复制性。

## 十、指标体系

**北极星指标：周活跃清单消费用户数**（浏览 / 收藏 / 订阅清单的去重用户）。

| 层 | 指标 |
|---|---|
| 供给 | 公开清单渗透率（发布用户 / MAU）、人均清单数、清单月更新率 |
| 分发 | 店页 / 搜索清单模块曝光点击率、清单 → 门店页转化率 |
| 消费 | 清单收藏 / 订阅数、更新召回打开率、"拔草"回访率 |
| **增长（活动）** | 提报清单数与达标率、参赛清单收藏 UV、**有效拔草打卡数 / 拔草率**、拉票卡站外回流占比、赛后 30 天参赛清单更新率 |
| 信任 | 商业清单举报率、"真实去过"覆盖率、活动无效打卡剔除率（逐轮公示） |
| 大盘 | 决策渗透（经清单到店的决策占比）、次月留存增量，最后才是 DAU |

> 口径衔接：私藏杯的"有效拔草打卡"就是"经清单到店"的可归因样本——活动结算数据赛后直接沉淀为分发权重的真值集。

## 十一、一句话收拢

这个产品成立的前提，是点评愿意把一部分"店的流量"让渡给"人"。私藏好店能不能成，产品设计只占一半，另一半取决于分发上是否真的敢在门店页和搜索里给清单留出一级位置——如果只是加一个藏得很深的新功能，它会变成又一个收藏夹。

而让它"活过来"的那把火，是私藏杯：**产品把"人 → 店"的路铺好，活动让全城在同一周里真的走上这条路。** 只要守住两条底线——票是真的、清单是干净的——这场比赛就会替产品回答那个最关键的问题：人的品味，到底能不能把人带到店里去。
