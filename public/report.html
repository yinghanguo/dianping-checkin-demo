01项目背景与机会
一条已经存在、但点评没有承接的找店路径
现状

品类 → 店

用户在点评找店的唯一路径：搜索、榜单、评分。十几年未变，信任来源是统计。

机会

人 → 店

现实中信任度更高的路径："问那个会吃的朋友"。它今天发生在微信对话框里——"发我你那个火锅清单"——点评并没有承接它。

「私藏好店」要做的，就是把这条路径产品化：让"会吃的朋友"的个人品味被便捷地创作成清单，并在信息流、好友列表、搜索结果页、门店详情页等主链路分发。
02产品定义
私藏好店在现有体系中的坐标
单元信任基础时效性资产归属
评价单店单次体验统计信任（量大取平均）低衰减店
打卡单店行为记录无（"我来过"的足迹）无人（足迹）
官方榜单多店集合平台信任（算法与规则）周期更新平台
私藏好店多店 + 一个主题口径品味信任（信这个人）低衰减，可持续更新人
官方榜单是"统计的答案"，私藏好店是"某个人的答案"——二者在分发场景中互补并存。
属性一

是策展，不是记录

价值不在单店信息，而在选择与排除——"他只放了这八家"本身就是信息。评价越多越准，清单越少越贵。

属性二

是活的文档

可持续增删维护，因此具备订阅价值：死内容只能被消费一次，活清单让人反复回来。

属性三

以人为索引

第一次为点评提供"人 → 店"的找店路径，是"会吃的朋友"这一现实行为的产品化。

类比：清单之于门店，如歌单之于歌曲

Spotify 的歌单没有生产任何新歌，但重构了消费入口，并让"品味"本身成为可关注的对象。

形态最低规格

清单 = 主题 + N 家门店 + 每店一句话理由（结构化最低要求）。没有理由是店铺堆砌，"他家只有中午去才有那个汤"才是品味的证据。支持私密 / 公开，公开只是一个开关。

03产品路径设计
创作 · 分发 · 存放
创作的关键设计原则：清单是"攒"出来的，不是"写"出来的。做成从零开始的创作任务，供给必然起不来。
① 存量转化 · 最重要

收藏夹一键生成清单；从历史打卡 / 高分评价反向聚合——"你打过卡的咖啡店已有 23 家，整理成一份私藏好店？"AI 生成草稿，用户只做删减和补一句话理由。

② 顺手收集

门店页"收入私藏"按钮（类似加购物车）；写完评价后追问"加进你的某个清单吗？"——让创作分散在日常使用中。

③ 主动创作

个人主页"新建清单"，服务头部创作者。

分发：清单在哪被看见（按效率排序）

场景形式逻辑
门店详情页高互动清单模块 +「被 N 份私藏收录」店是天然流量入口，借店的流量给人导流；清单反向为店提供比评分更立体的背书
搜索结果页店铺结果中穿插清单卡片命中高决策成本场景——用户要的不是排序，是"一个靠谱的人替我选好"
信息流清单卡片、"好友更新了私藏"事件品味浏览与关系链消费
好友列表 / 主页「TA 的私藏」一级入口人 → 店路径的起点
地图（V1.1 新增）「私藏」图层（与必吃榜并列）：热门门店 pin 追加收录标记 → 底部清单列表 → 点选后清单门店连成路线上图信息流分发内容，地图分发决策；清单在地图上变成"可以走的路线"，从决策工具升级为行动工具
站外分享精致的微信卡片"发我你那个清单"是已存在的真实需求，最便宜的外部增长

存放：工具与表达合一

存放位置决定产品性质：放在"收藏"是工具，放在"个人主页"是表达。答案是两者合一——清单不新建体系，而是给点评已有的「专辑」接电：收藏 → 归入专辑（私密整理）→ 补一句理由 + 公开 = 私藏清单。一个对象三种状态，工具层已存在，缺的只是表达层与分发层；公开清单成为个人主页的一级门面"品味橱窗"。

私密工具价值兜底 100% 用户的使用理由，公开表达只是一个开关。

供给漏斗自然形成

收藏
100% 用户的工具行为
归入专辑
私密整理，仍是工具（点评已有）
公开清单
补一句理由 + 一个开关，成为表达
04用户与增长
创作金字塔 · 冷启动 · 规模化飞轮

创作侧是金字塔，不幻想全民创作

头部 ~1%"会吃的朋友"：高等级会员、精评达人、本地 KOC —— 分发级供给
腰部 ~5–10%有整理欲的重度用户 —— 供给主力与扩散层
长尾 100%把清单当私密收藏工具 —— 腰部与头部的蓄水池

消费侧是全量决策用户

优先覆盖高决策成本场景：宴请、约会、出差、陪外地朋友——这些场景下清单对评分的替代优势最大。

冷启动四件事

① 供给不靠激励靠存量：AI 基于十几年评价/打卡/收藏数据生成草稿清单，定向"一键认领发布"，第一批供给近乎零成本；
② 定向邀请 + 官方打样：城市 KOC 种子创作者 + 官方共创标杆清单，定义什么是好清单；
③ 打透一两个城市：清单价值依赖同城密度，先在上海或成都做到"搜任何主流品类都能撞到好清单"；
④ 选对首发场景：从"问朋友才敢决策"的品类切入。

规模化飞轮

1
曝光店页 / 搜索给清单分发位（冷启动期流量倾斜，平台保证这一环）
2
互动清单获得点赞、收藏、订阅
3
维护创作者得到反馈，持续修剪与新建
4
再分发更新行为触发新一轮分发
↻ 更新回到曝光，飞轮闭环
对 DAU 保持诚实：点评是低频决策工具，清单不会把它变成小红书。但它带来两类真实的频次增量——创作者的维护频次（清单是活的，需要回来修剪）和消费者的"拔草"回访（收藏清单后勾掉去过的店，清单变成待办列表；叠加"你订阅的私藏更新了"召回，建立点评目前缺失的"订阅—更新"内容循环）。
合理预期：留存和决策渗透先动，DAU 后动。
05风险与对策
按严重程度排序
1

商业化污染信任最大卡点

点评的立身之本是真实性，而清单的信任模型比评分更脆弱——评分靠量对冲水军，清单只要创作者被收买一次就整体崩塌；"推广清单"混入分发会让用户对整个体系的信任连坐。

对策（必须前置）：早期清单一律不可商业化；"真实去过"加权——清单内门店有创作者本人打卡 / 消费凭证的，分发权重更高；对店铺密集重合、集中新增的清单做算法识别与降权。

2

供给冷启动悖论

没人看 → 没人写。

对策：私密工具价值兜底，让创作在无人观看时也成立（收藏 → 私密清单 → 公开清单的漏斗设计）。

3

马太效应

头部达人吃掉全部分发，普通人失去动力。

对策：分发上"朋友的清单"权重高于"网红的清单"。这也是点评相对小红书的差异化——小红书给你陌生人的种草，点评给你认识的人的私藏。

4

清单腐烂

店会关、会变味，清单随时间失效。

对策：闭店自动标注、清单"健康度"分、更新行为触发再分发（把维护变成有回报的事）。

06产品命名
个人主页入口：「TA 的私藏」
私藏好店
这是我私藏的店，不轻易告诉别人
理由一

征用现成心智

"这是我私藏的店""分享几家私藏"是用户已经在说的话，零教育成本。

理由二

自带信任与稀缺感

"私藏"暗示不是广告、不是榜单——正面对冲最大的信任风险。

理由三

与产品路径严丝合缝

收藏 → 私藏 → 公开私藏；"公开我的私藏"本身就有社交张力，是天然的传播语。

07里程碑规划
三阶段，各验证一件事

Phase 1 · 工具期1 个月

  • 收藏体系升级为清单体系：私密 / 公开开关、每店一句话理由、门店页"收入私藏"
  • AI 存量转化：草稿清单生成 + 一键认领
  • 个人主页「TA 的私藏」模块
验证创作漏斗：收藏 → 私密清单 → 公开清单的转化率

Phase 2 · 分发期1–2 个月

  • 门店详情页清单模块 +「被 N 份私藏收录」
  • 搜索结果页清单卡片穿插（先约会 / 宴请 / 深夜食堂等高决策品类）
  • 微信分享卡片；种子城市 KOC 邀请计划与官方共创标杆清单
验证分发效率：清单卡片点击率、清单到店转化

Phase 3 · 循环期2–3 个月

  • 清单订阅与更新召回、"拔草"勾选机制
  • 信息流清单卡片与好友关系链事件
  • 反作弊体系（真实去过加权、商业密度识别）全量；城市复制
验证"订阅—更新"循环对留存的拉动

一句话收拢
这个产品成立的前提，是点评愿意把一部分"店的流量"让渡给"人"。私藏好店能不能成，产品设计只占一半，另一半取决于分发上是否真的敢在门店页和搜索里给清单留出一级位置——如果只是加一个藏得很深的新功能，它会变成又一个收藏夹。
